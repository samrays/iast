# API Specification

The authoritative machine-readable contract is the OpenAPI document generated by FastAPI at
`GET /openapi.json` (rendered at `/docs`). This document specifies the conventions that generator
follows and the surface for each phase.

## 1. Conventions

| Aspect | Rule |
|---|---|
| Base path | `/api/v1` |
| Media type | `application/json`; errors use `application/problem+json` (RFC 9457) |
| Case | `snake_case` in payloads (matches the Python domain and the SQL schema) |
| Time | RFC 3339 UTC with `Z` suffix |
| Identifiers | UUID strings |
| Versioning | Additive-only within `v1`; breaking changes create `v2`. Deprecations carry a `Sunset` header |
| Idempotency | `Idempotency-Key` header required on `POST` that creates billable or side-effecting resources |
| Tracing | `traceparent` accepted and propagated; `X-Request-Id` echoed |

### 1.1 Error envelope

```json
{
  "type": "https://docs.aegis.dev/errors/permission-denied",
  "title": "Permission denied",
  "status": 403,
  "detail": "This action requires the finding:triage permission.",
  "instance": "/api/v1/findings/018f.../status",
  "request_id": "01J8W9...",
  "errors": [
    { "field": "status", "code": "invalid_transition", "message": "OPEN -> REMEDIATED is not allowed" }
  ]
}
```

| Status | Used for |
|---|---|
| 400 | Malformed syntax |
| 401 | Missing or invalid credentials |
| 403 | Authenticated but lacking permission |
| 404 | Not found **or** not visible to this tenant (never 403 for cross-tenant) |
| 409 | Conflict — unique violation, invalid state transition, optimistic-lock failure |
| 422 | Schema validation failure |
| 423 | Account locked |
| 429 | Rate limited — includes `Retry-After` |
| 5xx | Server error — never leaks internals; `request_id` is the support handle |

### 1.2 Pagination

Cursor-based (keyset) for every collection. Offset pagination is not offered — it degrades and it
double-reports on live data.

```
GET /api/v1/findings?limit=50&cursor=eyJsYXN0X3NlZW5fYXQiOi4uLn0
```

```json
{
  "items": [ ... ],
  "page": { "next_cursor": "eyJ...", "has_more": true, "limit": 50 }
}
```

`limit` defaults to 50, maximum 200.

### 1.3 Filtering, sorting, sparse fields

```
GET /api/v1/findings
    ?status=OPEN,CONFIRMED
    &severity=HIGH,CRITICAL
    &application_id=018f...
    &first_seen_after=2026-01-01T00:00:00Z
    &q=deserialization
    &sort=-risk_score
    &fields=id,title,severity,risk_score,last_seen_at
```

Filter values are enum-validated; unknown parameters are rejected with 422 rather than ignored.

### 1.4 Authentication

Three principal types, distinguished by the JWT `aud` claim; endpoints declare which they accept.

| Principal | Credential | Audience | Lifetime |
|---|---|---|---|
| User | `Authorization: Bearer <access_jwt>` | `aegis:user` | 15 min access, refresh via rotating opaque token |
| Service / CI | `Authorization: Bearer <api_key>` where key is `ak_<prefix>.<secret>` | n/a | Until revoked or expired |
| Agent | `Authorization: Bearer <agent_jwt>` | `aegis:agent` | 24 h, renewed on heartbeat |

Access-token claims:

```json
{
  "iss": "https://api.aegis.dev",
  "aud": "aegis:user",
  "sub": "018f2b...",
  "org": "018f1a...",
  "sid": "018f3c...",
  "perms": ["app:read", "finding:read", "finding:triage"],
  "mfa": true,
  "iat": 1785000000,
  "exp": 1785000900,
  "jti": "01J8W9..."
}
```

The `perms` claim is an optimization for the gateway; **the application layer re-resolves permissions
from the database on every authorization decision**, so a revoked role takes effect immediately rather
than at token expiry.

### 1.5 Rate limits

| Scope | Limit | Headers |
|---|---|---|
| Unauthenticated auth endpoints | 10/min per IP | `RateLimit-Limit`, `RateLimit-Remaining`, `RateLimit-Reset` |
| Authenticated user | 600/min | same |
| API key | 6000/min | same |
| Agent ingest | Per-tenant quota, negotiated by licence tier | gateway-side |

## 2. Phase 2 surface — Identity, Tenancy, Inventory

### Authentication

| Method | Path | Permission | Description |
|---|---|---|---|
| `POST` | `/auth/register` | public | Create an organization and its first owner. Disabled when self-service signup is off |
| `POST` | `/auth/login` | public | Exchange credentials for tokens. Returns `mfa_required` challenge when enrolled |
| `POST` | `/auth/mfa/verify` | mfa challenge token | Complete an MFA challenge |

| `POST` | `/auth/logout-all` | user | Revoke every session in the user's families |
| `POST` | `/auth/password/change` | user | Change password; revokes all other sessions |
| `POST` | `/auth/password/forgot` | public | Always 202, regardless of whether the address exists |
| `POST` | `/auth/password/reset` | reset token | Consume a single-use reset token |
| `GET` | `/auth/me` | user | Current principal, organization, roles, effective permissions |
| `POST` | `/auth/mfa/enroll` | user | Begin TOTP enrolment; returns provisioning URI and recovery codes once |
| `POST` | `/auth/mfa/confirm` | user | Confirm enrolment with a valid code |
| `DELETE` | `/auth/mfa` | user + password | Disable MFA |

## 4. GraphQL

A read-only GraphQL endpoint at `/api/v1/graphql` serves the dashboard's composite views (a single
round trip for an application page that needs findings + risk + agents + routes). It shares the same
authentication and permission resolution as REST, adds per-query depth and complexity limits, and
disables introspection in production.

## 5. Streaming

| Channel | Transport | Event types |
|---|---|---|
| `/api/v1/events/stream` | SSE | `finding.created`, `finding.updated`, `attack.detected`, `agent.status_changed` |
| `/api/v1/analysis/{id}/stream` | SSE | `token`, `artifact`, `done`, `error` |

SSE was chosen over WebSocket for the dashboard: the traffic is server-to-client only, it survives
HTTP/2 multiplexing and corporate proxies, and it reconnects with `Last-Event-Id` for free.

## 6. Agent wire protocol (gateway)

Distinct from the user API — protobuf over gRPC, defined in `packages/proto/agent/v1/`.

```protobuf
service AgentIngest {
  rpc Register       (RegisterRequest)        returns (RegisterResponse);
  rpc StreamEvents   (stream RuntimeEvent)    returns (stream IngestAck);
  rpc Heartbeat      (HeartbeatRequest)       returns (HeartbeatResponse);
  rpc FetchConfig    (ConfigRequest)          returns (ConfigResponse);
}
```

An HTTP/JSON fallback exists for environments that cannot run gRPC; it accepts newline-delimited JSON
batches at `POST /ingest/v1/events` with the same schema and gzip/zstd compression.
